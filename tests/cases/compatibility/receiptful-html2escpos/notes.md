# Receiptful html2escpos compatibility

This stream was generated by Receiptful's public
`app.html2escpos.render()` function with the `NT-5890K` profile. Keeping the
result as immutable input proves that escpos2png continues to render commands
produced by the current application without depending on Receiptful at
runtime.

The source HTML was:

```html
<h1>Receiptful</h1>
<p align="center">
  <b>Bold</b> <u>Under</u> <small>Small</small> <inv>Inverse</inv>
</p>
<table>
  <colgroup><col width="18"><col width="14"></colgroup>
  <tr><td>Latte</td><td align="right">3.50</td></tr>
</table>
<hr width="50%" align="center">
<feed height="8px">
Done
```

Receiptful generated the 225-byte stream in its API container. Git versions
the fixture together with its manifest and expected PNG. It covers the real
emitter's:

- explicit initial text-state reset;
- `ESC t` code-table selection;
- text sizing, alignment, emphasis, underline, Font B, and reverse mode;
- fixed-width table text; and
- `GS v 0` output used for the horizontal rule and pixel-height feed.

The source intentionally omits paper cutting and drawer pulses so the fixture
is safe to send to a physical printer. Those non-visual commands have separate
public renderer tests.

This is a compatibility snapshot, not a dependency between the two projects.
If Receiptful intentionally changes its emitter, regenerate the bytes through
its Docker Compose API service, review the rendered dot differences, and
update this case deliberately.
